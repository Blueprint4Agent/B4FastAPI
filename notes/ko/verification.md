# 변경 범위별 검증

`make verify-plan`으로 계획을 확인하고 `make verify`로 실행합니다. 로컬 훅과 수동 Actions가 같은 `scripts/verification.py` 분류기를 사용합니다. 이 규칙은 작은 변경에도 전체 check/test/build를 요구하던 기존 목록보다 우선합니다. Git 규칙 검사·PR·병합 보호는 유지합니다.

| 범위 | 기준 | 검사 |
| --- | --- | --- |
| 문서 | 알려진 Markdown 문서·작업 기록, AGENTS.md 제외 | 변경 텍스트·공백·UTF-8 |
| 문구 | 기존 번역 JSON의 문자열 값만 변경, 키·치환 변수·중첩 참조·태그 유지 | JSON 문법·중복 키·텍스트 |
| 동작 | 보호 대상 이외 유틸리티·훅·테스트, 백엔드 앱·테스트 | 해당 영역 검사·테스트, 프론트엔드 빌드 |
| UI | 컴포넌트·페이지·스타일·정적 자산·브라우저 테스트 | 프론트엔드 검사·테스트·빌드·브라우저 UI |
| 전체 | 인증·세션·API·연결 복구·계약·의존성·설정·CI·도구, 알 수 없는 경로/이력 | 전체 관련 검사, 프로덕션 경로·스타일 편집기, 상위 통합·패키징 |

혼합 변경은 더 강한 범위를 선택합니다. 백엔드 변경은 인증·권한·데이터 경로를 포함한 백엔드 전체 테스트를 유지합니다. 프론트엔드 동작 변경도 짧고 공통 의존성을 보호하는 Vitest 전체를 유지합니다. 테스트를 파일 이름만으로 추측해 제외하지 않습니다. 검사 축소 옵션이나 PR 라벨 우회는 없습니다. 번역 파일 추가·삭제, 키 변경, 치환 변수/태그 변경, 배열·비문자열 값은 전체 검사입니다. 문구 길이가 레이아웃에 영향을 주면 담당자가 해당 화면 확인을 추가합니다.

기본 비교는 HEAD 대비 staged·unstaged·untracked 변경입니다. 브랜치 전체는 `VERIFY_BASE=$(git merge-base origin/main HEAD) make verify`로 검사합니다. 푸시 훅은 원격 main의 merge-base부터 실제 푸시 HEAD까지 비교하므로 앞선 변경도 검사합니다. 수동 Actions는 전체 검사입니다. `VERIFY_FULL=1 make verify`는 전체 검사를 강제하고 `make verification-test`는 실제 Git fixture로 분류를 검증합니다.

상위 저장소는 프론트엔드 gitlink 양쪽 커밋과 로컬 하위 변경을 확인합니다. 문구만 바뀐 pin 갱신도 경량 처리가 가능하며 하위 이력이 없으면 프론트엔드 전체 검사를 선택합니다. 하위 저장소 독립성을 위해 분류기와 테스트를 양쪽에 동일하게 유지합니다. 런타임 pin 변경의 계약·패키징 검사는 유지합니다. 경량 검사는 npm/uv 설치나 로컬 환경 비밀값 읽기가 필요하지 않습니다.

GitHub 워크플로는 수동 실행만 유지하고 필수 CI 상태를 제거합니다. PR·대화 해결·삭제/강제 푸시 금지와 필수 승인 0은 유지합니다. [로컬 훅](local-hooks.md)을 참고하세요.

동일한 관련 내용으로 통과한 위임 검사는 반복하지 않습니다. 명령·비교 기준·선택 범위·생략 이유를 작업 기록에 남깁니다. 새 동작 수정은 기존 동작 검증을 무효화하지만 문구만 후속 수정했다면 로컬에서는 해당 검사만 진행합니다. 푸시 훅은 브랜치 전체를 검사합니다. 같은 작업은 하나의 PR에 모으고 하위 병합 후 상위 pin을 한 번 갱신합니다. 로컬 로그 요약과 실패 부분부터 확인합니다. 동일 소스·설정·도구·산출물의 성공 기록은 최대 24시간 재사용하며 변경·실패 시 무효화합니다. 텍스트·거버넌스는 매번 검사하고 worklog 결과 기록만의 수정은 무거운 검사를 반복하지 않습니다. VERIFY_FULL=1과 수동 Actions는 재사용하지 않습니다.

실행기는 범위·명령·시간 요약을 출력하고 전체 로그는 저장소 Git 디렉터리의 `verification-logs/`에 보관합니다. 실패하면 마지막 80줄과 실패 종료 코드를 전달합니다. `python3 scripts/verification.py plan --json`으로 전체 계획을 확인할 수 있습니다. 상위 전체 검증은 프로덕션 경로 검사에서 빌드한 dist를 재빌드 없이 패키징하며, 별도 브랜드 설정의 독립 빌드 검사는 유지합니다.

## 영향 범위별 검사와 결과 재사용

결제·관리자 페이지/기능/도메인 훅 변경은 등록된 해당 단위·통합·브라우저 테스트를 선택합니다.
CSS는 변경 규칙 전체가 해당 도메인으로 제한될 때만 좁힙니다. 공통 선택자·변수·키프레임이나
분석할 수 없는 문법은 전체 UI 검사로 되돌아갑니다. 브라우저 테스트 본문만 바뀌면 해당 생성
테스트 그룹을 줄 번호로 선택하며, 설정·삭제 변경은 스펙 전체를 실행합니다. 인증/API/설정과
알 수 없는 변경은 전체 검증을 유지하고, 백엔드는 권한·데이터 결합 때문에 기존 전체 검사를 유지합니다.

정적 검사·타입·계약·빌드·Git 규칙은 유지합니다. 선택한 테스트 목록을 계획과 결과 지문에 포함해
다른 범위의 결과를 재사용하지 않습니다. CI 및 `VERIFY_FULL=1`은 전체를 새로 실행합니다.

한 작업에서는 같은 셸/도구 환경에서 상위 폴더의 `make -C src/frontend verify`,
`git -C src/frontend push`를 사용하고 상위 검증으로 이어갑니다. PATH 중복 및 Git 훅이 추가한
도우미 경로만 정규화하며 실제 경로 우선순위·실행 도구·버전·설정·소스·빌드 산출물 변경은
재검증합니다. 셸마다 Python 설치가 다르면 재검증하는 것이 정상입니다. 캐시 미적중 이유는
설정 값을 노출하지 않고 출력합니다. 브랜딩 생성 후 자식 검사를 실행하고, 빌드/라우트 결과도
공유합니다. 상위 계약·패키징 검사는 항상 유지합니다.

등록된 컴포넌트의 JSX 반환 영역만 변경되고 준비 코드·헬퍼·뒤쪽 코드가 동일하면 검토된 렌더링
시나리오를 제목으로 찾아 선택합니다. CSS의 변경 선택자가 모두 등록된 컴포넌트로 연결되지
않거나 테스트 제목이 사라지면 도메인 전체 검사로 되돌아갑니다. 훅 로직 변경은 도메인 검사를
유지합니다. 선택된 브라우저 사례는 기존 워커 수 제한 내에서 격리된 컨텍스트로 병렬 실행합니다.
`check-affected`는 전체 타입/구조/UI/상태 규칙과 변경 파일 포맷을 확인하며 변경 없는 도구 자체
테스트·API 재생성을 반복하지 않습니다. 도구·설정 변경은 기존 전체 `check`를 실행합니다.

## 검증 시간 측정 결과 — 2026-10-07

직전 결제·관리자 UI 변경을 같은 비교 범위로 사용했습니다.

`/usr/bin/time -p`로 측정한 로컬 1회 실행의 실제 경과 시간입니다.
모든 변경에서 같은 시간을 보장하는 수치는 아닙니다.

최종 첫 실행은 정적 규칙·타입·변경 파일 포맷 검사 9.3초, 관련 일반 테스트 2.2초,

첫 검증 시간은 **약 75% 감소**했습니다. 상위 통합에서도 계약 검사와 패키징은 유지합니다.
도메인만 선택했던 중간 결과는 101.16초였고, 최종 30.72초에는 컴포넌트 렌더링 영향 분석,
변경 대상 정적 검사, 격리된 브라우저 병렬 실행까지 적용됐습니다.

기존 자식 로그인 셸은 Python 3.9, 상위 셸은 Python 3.14를 선택했습니다.
개선 후에는 같은 상위 셸에서 `make -C` / `git -C`로 실행 환경을 통일했습니다.
따라서 순수 분류기만의 미세 벤치마크가 아닌 작업 흐름 전체의 개선 수치입니다.
실제 도구 환경이 달라지면 결과를 재사용하지 않습니다. 실결제·이메일 발송은 하지 않았습니다.

백엔드만 변경한 전체 실행은 별도로 실측하지 않았습니다. 백엔드 단계가 약 44초였으므로
백엔드만 약 45초, 이번 UI와 백엔드가 함께 바뀌면 약 75초는 **단계 합산 예상치**입니다.
인증·공통 코드·검증 도구 등 영향이 넓거나 불명확한 변경은 전체 검사를 유지합니다.
이번 전체 검증은 약 200초 수준이며, 캐시 재사용은 입력과 산출물이 동일할 때만 가능합니다.

최종 UI 측정 명령:

```sh
VERIFY_BASE=ca3f83f VERIFY_HEAD=57a67d5 make -C src/frontend verify
# 같은 명령을 다시 실행해 결과 재사용 시간을 측정합니다.
VERIFY_BASE=06e55ba VERIFY_HEAD=7c4922e make verify
```

원본 로컬 로그: `/tmp/b4-verify-baseline-first.log`,
`/tmp/b4-verify-baseline-integration.log`, `/tmp/b4-verify-refined-first.log`,
`/tmp/b4-verify-refined-repeat.log`, `/tmp/b4-verify-refined-integration.log`.
벤치마크는 이미 머지된 UI 변경 범위를 명시해서 비교합니다.
검증 도구 구현 변경 자체는 별도로 브랜치 전체 범위 검증을 수행합니다.
