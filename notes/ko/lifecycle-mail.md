# 생명주기 이메일 발송·복구

[English](../lifecycle-mail.md). #95는 [결제 점검](billing-audit-93.md)을 바탕으로 진행했습니다.
기존 0011 마이그레이션을 사용하며 이번에는 스키마 변경이 없습니다.

## 발송 기준

| 계기 | 수신자·확정 조건 | 안내 |
| --- | --- | --- |
| 최초 `invoice.paid` | 활성 로컬 계정 이메일. 서명·모드·고객 일치, 최초 paid 청구서의 완전한 단일 항목 가격과 현재 활성 구독 가격 일치 | 구독 시작 |
| `customer.subscription.updated` | 활성 로컬 계정 이메일. 실제 가격 전환, 현재 active·결제 대기 없음, 제공자 현재 가격이 이벤트와 일치 | 적용된 요금제 변경 |
| `customer.subscription.deleted` | 활성 로컬 계정 이메일. cancellation_requested로 종료되고 새 비종료 구독 없음 | Free 전환 완료 |
| 계정 삭제 | 본인 삭제 인증을 통과한 계정 이메일. 삭제와 outbox 예약이 같은 DB 트랜잭션으로 완료 | 계정 삭제 완료 |

해지 **예약**, 복원, 결제 실패·추가 인증·갱신, 복귀 URL, 결제 대기 업그레이드,
알 수 없는 가격은 앱 생명주기 메일을 보내지 않습니다. 상태 동기화 이벤트 범위는 결제 가이드를 따릅니다.
항목이 누락·복잡·잘렸거나 최초 가격이 오래된 청구서는 안내를 생략하며 Stripe 영수증을 기준으로 봅니다.
복잡한 청구 상품을 지원하려면 별도 안내 정책이 필요합니다.

금전 영수증·갱신 알림·실패/인증 복구는 Stripe, 위 계정/플랜 안내는 앱이 담당합니다.
운영 전 Dashboard 고객 메일·결제 복구 스위치를 확인해야 하며 기본 활성화를 가정하지 않습니다.
Stripe 해지 완료 안내도 켠 경우 완료 메시지 담당을 하나로 정합니다. 앱이 API로 제공자 메일을 끄지는 않습니다.
공식 [영수증](https://docs.stripe.com/receipts),
[고객 메일](https://docs.stripe.com/billing/revenue-recovery/customer-emails)을 참고하세요.

결제 메일 언어는 현재 Stripe Customer `preferred_locales` 중 첫 지원 언어(ko/en, 지역 접미사 지원)를
사용하고 없으면 영어입니다. 예약 시 암호화한 payload에 저장합니다. 해당 고객의 제공자 언어 설정을
지정해야 하며 앱 표시 언어 변경만으로 Stripe에 저장되지는 않습니다.
삭제 완료는 인증된 삭제 요청의 Accept-Language를 사용합니다.
한국어/영어 제목·HTML·일반 텍스트·버튼/대체 링크를 제공하며 결제는 `/settings?section=billing`,
삭제는 `/home`으로 연결합니다. 삭제 인증 코드 메일은 완료 메일과 별개이며 완료 CTA가 없습니다.

## 유실·중복 처리

MailQueueService가 기존 Celery `b4fastapi.notifications.drain`을 빈 payload로 깨우고,
MailService와 기존 브랜드 템플릿으로 발송합니다. Beat는 매분 조회하므로 브로커 깨우기 실패로
커밋한 예약이 유실되지 않습니다. Worker와 Beat 하나를 실행해야 하며 HTTP 요청에서 SMTP를 실행하지 않습니다.

삭제와 예약은 함께 커밋됩니다. outbox 저장이 실패하면 삭제도 롤백됩니다.
커밋 후 Redis 정리·브로커 실패는 사용자를 복원하지 않으며 예약도 남습니다.
결제는 Stripe와 DB를 같은 트랜잭션으로 묶을 수 없습니다. 서명 웹훅에서 현재 상태를 조회·동기화한 뒤,
outbox 저장까지 마친 후 성공을 응답합니다. 예약 전 실패는 비성공 응답으로 제공자 재전송을 유도합니다.
결제 변경 요청에서 이메일을 별도로 직접 발송하지 않습니다. 오래된 이벤트는 의도적으로 생략하며
Beat는 구독 상태를 복구할 뿐 과거 안내 이벤트를 재생성하지는 않습니다.

시작/종료는 구독 의미 키, 적용된 변경은 구독+이벤트 ID로 중복 제거합니다.
초 단위 타임스탬프를 키로 사용하지 않아 같은 초의 반복 전환을 합치지 않습니다.
이전 타임스탬프/가격 키도 확인해 업그레이드 후 과거 메일 재발송을 막습니다.
구·신 생산자를 동시에 운영하면 다른 키 형식 간 원자적 중복 제거는 보장할 수 없으므로 버전을 맞춰 배포합니다.
동일 의미라도 Stripe 이벤트 ID가 다르면 별도 안내가 생성될 수 있으며 이벤트·SMTP의 정확히 한 번 발송을
보장하지 않습니다. [공식 이벤트 순서 안내](https://docs.stripe.com/webhooks#event-ordering)를 참고하세요.
현재 제공자 상태를 다시 검증해 오래된 플랜 안내를 억제합니다.

## 재시도·보존·접근 범위

각 시도는 5분 임대를 사용하며, 완료 기록 없이 종료된 워커도 포함해 최대 5회 점유합니다.
SMTP 실패 후 2·4·8·16분 간격으로 재시도하고 다섯 번째 실패는 최종 실패입니다.
다섯 번째 임대가 만료되면 `failed / delivery_unconfirmed`, SMTP 예외는
`failed / delivery_failed`로 기록합니다. 이전 임대 작업은 후속 결과를 덮어쓸 수 없습니다.
로그에는 작업 ID·시도·정해진 오류 분류·운영자만 남기며 수신 정보나 제공자 예외 본문은 남기지 않습니다.

payload는 SECRET_KEY에서 도메인을 분리해 SHA-256으로 파생한 키와 Fernet 인증 암호화를 사용합니다.
새 삭제 완료 메일은 이메일·언어만 보존하고, 결제 메일은 인사 이름·플랜명도 암호화합니다.
사용자 FK가 없으므로 삭제 후 전달할 수 있습니다. API/Worker와 DB·키 접근을 가진 신뢰할 수 있는
배포 운영자만 접근해야 하며 DB 계정·파일·로그·백업 권한도 제한해야 합니다.
브로커에는 수신자와 암호문을 넣지 않습니다.

성공 또는 발송 비활성 처리 시 암호문을 즉시 지웁니다. 나머지는 최초 예약 후 72시간 만료이며
최종 실패도 포함해 매 조회 때 만료 payload를 지웁니다. 기한 이후 발송·수동 재시도는 금지합니다.
물리적 삭제는 다음 조회 때이므로 Worker·Beat 중단 시 지연됩니다. 조회 상태를 감시하고 복구 후 실행해야 합니다.
외부 백업은 배포 환경의 접근 제한·보존 정책을 따르며 Worker가 백업까지 지우지는 못합니다.
SECRET_KEY 교체 전 대기 메일을 처리해야 합니다.

수신자 없는 불투명 중복 키·종류·상태·시도·오류·만료 시각은 과거 이벤트 재예약 방지를 위해 계속 보존합니다.
수동 재시도는 시도 횟수만 초기화하고 **최초 만료 기한을 연장하지 않습니다**.
재시도 이력 보관이 필요하면 운영자 로그를 중앙 로그 저장소에 보존합니다.
SMTP 수락 직후 워커가 종료되면 중복 전달될 수 있으므로 불확실한 실패 재처리 전 제공자 로그를 확인합니다.

## 운영 명령

저장소 루트에서 다음과 같이 실행합니다. list는 읽기 전용이며 retry는 보존 중인 실패 한 건을 변경합니다.

```sh
cd src/backend
uv run python -m app.manage_notifications list --limit 50
uv run python -m app.manage_notifications retry <64자리-notification-id>
```

list는 수신 정보 없이 안전한 메타데이터만 만료 시각 내림차순으로 최대 100건 반환합니다.
retry는 이메일 비활성, 잘못된 ID, 만료/삭제/성공/생략/대기/발송 중인 작업을 거부합니다.
OS 운영자와 결과를 로그에 남기고 pending으로 커밋하면 다음 Beat 조회에서 처리합니다.
CLI는 암호 해독이나 SMTP를 수행하지 않습니다.
역할 관리 CLI처럼 배포 운영자 경계이며 앱 매니저·관리자 권한이 아닙니다.
일반 사용자·매니저·관리자 모두 타인 메일 조회/재처리 HTTP API는 제공하지 않습니다.
앱 역할을 근거로 셸·DB 접근을 부여하면 안 됩니다.

이메일 비활성 상태에서는 새 예약을 만들지 않고 기존 작업은 생략·삭제합니다.
계정 삭제는 기존 이메일 인증 코드 정책을 유지하므로 이메일 비활성 환경에서는 차단됩니다.
완료된 작업 뒤의 SMTP·브로커·워커 장애가 도메인 결과를 되돌리지는 않습니다.
키 불일치 암호 해독 실패도 제한된 시도 횟수에 포함합니다.

## 검증

DB 통합 테스트로 워커 중단 한도, 오래된 임대, SMTP·수동 복구, 최초 만료,
수신 정보 삭제·조회 비노출, 삭제 롤백·브로커 실패를 검증합니다.
서명 웹훅은 중복·역순·같은 초 전환, 재구독 후 해지, 청구서 형식·언어 선택을 검증합니다.
템플릿은 양 언어·이스케이프·일반 텍스트·CTA/대체 링크를 확인합니다.
외부 메일·실제 결제는 실행하지 않았습니다. 루트 Make 결과는
[작업 기록](../../worklog/0222-lifecycle-mail-recovery.md)에 있습니다.
운영 전 외부 웹훅·SMTP·Worker 배포 검증은 필요하며 로컬 테스트가 이를 활성화하지는 않습니다.
